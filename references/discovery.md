# Stage 1 — Product Discovery

Goal: turn an idea into a clear, grounded, viable product proposal **before** the PRD, screens, stack or architecture.

Depth scales with stakes: a personal or class project takes a few hours; a commercial SaaS takes interviews and several iterations. Never skip it, size it.

## Six steps

1. **Idea definition** — what you want to build, which problem it solves, what result you expect. No features yet.
2. **User research** — who will use it, their needs, frustrations, behaviors, and how they solve the problem today.
3. **Market research** — similar apps, competitors, workarounds (spreadsheet, WhatsApp, asking a general AI), differentiation opportunities.
4. **Value proposition** — why someone would use this instead of what they do now. If you cannot write it honestly in one sentence, rethink.
5. **Hypothesis validation** — list what you are assuming; check the riskiest ones with interviews, research or a cheap prototype. Each gets "how" and "when".
6. **Discovery document** — consolidate everything below.

Ask the user one question at a time (`superpowers:brainstorming`); start from their free description of the idea, even if messy.

## Deliverable

`docs/01-product-discovery.md` (small projects: a section at the top of `docs/prd.md`).

| Element | Expected result |
|---------|-----------------|
| Problem | The specific problem we will solve |
| Target users | Who they are |
| Needs | What they actually need |
| Competition | Alternatives that exist today, including a general AI |
| Differentiation | Why ours is worth using |
| Viability | Main risks and constraints |
| Validation | What we checked, what is still assumed, how and when it gets checked |
| Success | 2-3 metrics that tell us it worked |

## Done when

- [ ] Problem stated without naming features
- [ ] Users and their current workaround named
- [ ] At least 2 alternatives with why ours wins
- [ ] Riskiest assumption written down with how and when it is checked
- [ ] 2-3 measurable success metrics
